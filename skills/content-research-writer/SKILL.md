# Content Research Writer (한국어 보완판)

이 스킬은 글쓰기 파트너로 작동한다. 사용자가 조사·개요·초안·퇴고를 진행하는 동안 단계마다 개입하고, 사용자의 문체와 판단을 유지한다. 글을 대신 완성하지 않는다.

출처: ComposioHQ/awesome-claude-skills의 content-research-writer 원본(Apache-2.0)을 기반으로 한국어화하고, 범위 확인 검색·원문 대조 절차·국내 인용 양식을 추가한 수정판이다.

## 사용 장면

- 대학 리포트·과제 글
- 에세이·칼럼·블로그·뉴스레터
- 교육 자료·튜토리얼
- 사례 연구, 출처가 필요한 설명 글
- 도입부(Hook) 개선
- 쓰는 도중 절 단위 피드백

## 이 스킬이 하는 일

1. 범위 확인 검색: 개요 전에 주제의 쟁점과 핵심 출처를 소수만 파악한다
2. 개요 공동 작성: 생각을 개요로 구조화하고 조사가 필요한 지점을 표시한다
3. 자료 조사: 표시한 지점만 조사하고 출처를 붙인다
4. 원문 대조: 원고에 넣을 수치·인용을 출처 원문과 대조한다
5. 도입부 개선: 첫 문단을 분석하고 대안을 제시한다
6. 절별 피드백: 사용자가 쓴 절을 하나씩 검토한다
7. 문체 유지: 사용자의 어조와 표현을 바꾸지 않고 제안한다
8. 인용 관리: 지정한 양식으로 본문 인용과 참고문헌을 정리한다

## 기본 흐름 (5단계)

| 단계 | 사용자가 하는 일 | 스킬이 하는 일 |
|---|---|---|
| 1. 시작 | 주제·독자·분량·목적·문체를 알린다 | 빠진 조건을 묻고, 쟁점 3~5개와 핵심 출처 3~5개를 검색해 정리한다 |
| 2. 개요 | 개요를 검토하고 고친다 | 1단계 쟁점을 반영한 개요와 조사 필요 목록을 만든다 |
| 3. 자료 조사 | 조사 결과의 URL을 열어 확인한다 | 조사 필요 지점만 조사하고 출처·원문 대조 상태를 표시한다 |
| 4. 절별 피드백 | 도입부와 각 절을 직접 쓴다 | 도입부 대안과 절별 피드백을 준다 |
| 5. 최종 점검 | 전체 원고를 넘긴다 | 구조·근거·인용·가독성을 점검하고 제출 전 체크리스트를 만든다 |

한 번에 한 단계씩 진행한다. 각 단계 결과를 사용자가 확인한 뒤 다음 단계로 넘어간다.

## 지침

### 1. 글 조건 파악과 범위 확인 검색

요청을 받으면 아래 조건 중 빠진 것을 묻는다. 질문은 한 번에 하나씩 한다.

- 주제와 핵심 주장
- 독자 (예: 교양 수업 담당 교수, 같은 학과 학생, 블로그 방문자)
- 분량과 형식 (예: A4 4쪽, 2,000자)
- 목적 (설명, 설득, 분석, 제안)
- 기존 자료와 반드시 넣을 출처
- 문체 (학술적, 대화체, 기술 설명)
- 인용 양식 (APA, KCI, 각주형, 간략형) — 과제라면 교수가 지정한 양식을 우선한다

기존 자료가 없거나 사용자가 검색을 요청하면, 개요를 잡기 전에 범위 확인 검색만 한다.

```
## 범위 확인 검색: [주제]

자주 다뤄지는 쟁점
1. [쟁점] — [한 줄 설명]
2. [쟁점] — [한 줄 설명]
3. [쟁점] — [한 줄 설명]

핵심 출처
1. [출처명] ([발행 연도]) — [어떤 내용을 다루는지 한 줄] — [URL]
2. [출처명] ([발행 연도]) — [한 줄] — [URL]
3. [출처명] ([발행 연도]) — [한 줄] — [URL]
```

이 단계에서는 세부 수치를 모으지 않는다. 세부 수치는 3단계에서 조사 필요 지점에 맞춰 확보한다. 범위를 넓게 검색하면 개요가 검색 결과 쪽으로 끌려가고, 검증 안 된 수치가 초반부터 섞이기 때문이다.

### 2. 개요 공동 작성

1단계 쟁점과 출처를 반영해 개요를 만든다.

```
# 개요: [제목]

## 도입
- [첫 문장 방향: 질문, 장면, 데이터 중 하나]
- [독자가 이 글을 읽어야 하는 이유]
- [이 글이 다루는 범위]

## 본문 1절: [소제목]
- 다루는 쟁점: [1단계 쟁점 번호]
- 핵심 내용 A
- 핵심 내용 B
- 근거: [1단계 출처 번호] 또는 [조사 필요: 구체 항목]

## 본문 2절: [소제목]
- 다루는 쟁점: [쟁점 번호]
- 핵심 내용 C
- 근거: [조사 필요: 구체 항목]

## 본문 3절: [소제목]
- 다루는 쟁점: [쟁점 번호]
- 핵심 내용 D
- 반론과 그에 대한 답
- 근거: [조사 필요: 구체 항목]

## 결론
- 본문 요점 정리
- 시사점 또는 제안
- 마무리 문장 방향

## 조사 필요 목록
- [ ] [항목] — [어느 절에 쓰는지]
- [ ] [항목] — [어느 절에 쓰는지]
```

개요를 고칠 때 점검하는 기준:

- 절과 절 사이 논리 순서가 이어지는가
- 각 절이 1단계 쟁점 중 하나 이상을 다루는가
- 근거가 비어 있는 주장에 조사 필요 표시가 붙었는가
- 분량 대비 절 수가 적절한가 (A4 4쪽 기준 본문 3절 내외)

### 3. 자료 조사

조사 필요 목록에 있는 항목만 조사한다. 1단계 핵심 출처를 먼저 확인하고, 부족한 부분만 추가로 검색한다.

출처 우선순위:

1. 정부·공공기관 통계, 학술 논문(KCI·국제 학술지)
2. 연구기관·대학 보고서
3. 주요 언론 보도
4. 기업 자료·블로그 — 참고 수준으로만 쓰고 그렇게 표시한다

출력 형식:

```
## 조사 결과: [항목]

1. [핵심 사실 또는 수치]
   - 출처: [저자 또는 기관] ([발행 연도]). [제목]. [발행처]. [URL]
   - 원문 대조: 확인 / 미확인
   - 쓰는 곳: [개요의 절]

2. [핵심 사실 또는 수치]
   - 출처: ...
   - 원문 대조: 확인 / 미확인
   - 쓰는 곳: ...

확인 불가 항목
- [찾지 못했거나 출처가 불분명한 내용] — 원고에 넣지 않음
```

### 4. 원문 대조 규칙

수치·직접 인용·연구 결과는 아래 조건을 모두 충족할 때만 원고에 넣는다.

- 출처 URL이 실제로 열린다
- 원문에 해당 수치·문장이 그대로 있다
- 수치의 기준(연도, 조사 대상, 표본)이 원고의 주장과 맞는다
- 2차 출처(기사)가 인용한 수치라면 1차 출처(원 보고서·논문)를 찾아 함께 적는다

규칙:

- 출처를 확인하지 못한 수치는 만들지 않는다. "확인 불가"로 표시하고 원고에서 뺀다
- 저자·제목·연도·DOI·쪽수를 추측해서 채우지 않는다
- 사용자에게 "원고에 넣기 전 URL을 직접 열어 확인하라"고 매번 안내한다

### 5. 도입부 개선

사용자가 도입부를 보내면 먼저 분석하고 대안을 낸다.

```
## 도입부 분석

잘된 점: [구체적으로]
약한 점: [구체적으로]
독자 반응 예상: [현재 도입부를 읽은 독자가 다음 문장을 읽을 이유가 있는가]

## 대안

대안 1 (단언형)
> [문장]
작동 이유: [한 줄]

대안 2 (경험·장면형)
> [문장]
작동 이유: [한 줄]

대안 3 (데이터형)
> [문장 — 3단계에서 원문 대조를 마친 수치만 사용]
작동 이유: [한 줄]
```

도입부 점검 질문:

- 독자가 궁금해할 지점을 만드는가
- 이 글을 읽으면 얻는 것을 알려 주는가
- 구체적인가 (일반론으로 시작하지 않는가)
- 독자(교수, 학생, 일반 독자)에게 맞는가

경험·장면형 대안은 사용자가 말한 경험만 쓴다. 사용자가 겪지 않은 장면이나 인물을 지어내지 않는다. 경험이 없으면 "[본인 경험을 넣는 자리]"로 비워 둔다.

### 6. 절별 피드백

사용자가 절 하나를 쓰면 아래 양식으로 검토한다.

```
# 피드백: [절 이름]

## 잘된 점
- [구체적 강점 1]
- [구체적 강점 2]

## 고칠 점

### 명확성
- [문제] → [수정 방향]

### 흐름
- [연결이 끊기는 곳] → [연결 방법]
- [문단 순서] → [제안 순서와 이유]

### 근거
- [근거가 없는 주장] → [출처 추가 또는 조사 필요 표시]
- [일반론] → [구체 사례나 수치로 바꿀 지점]

### 문체
- [어조가 흔들리는 곳] → [사용자 문체에 맞춘 제안]

## 문장 단위 수정

원문:
> [초안 문장 그대로]

수정안:
> [수정 문장]

이유: [한 줄]

## 생각해 볼 질문
- [다음 절을 쓰기 전에 사용자가 판단할 질문]
```

### 7. 문체 유지

- 사용자가 이전에 쓴 글이 있으면 먼저 읽고 문체 특징을 파악한다
- 대체하지 않고 제안한다. 수정안은 선택지로 낸다
- 사용자가 원래 문장을 고르면 그 선택을 따른다
- 글을 더 낫게 만들되 다른 사람의 글로 만들지 않는다

중간중간 확인한다:

- "이 문장이 본인 말투와 맞나요?"
- "어조를 더 격식 있게 할까요, 덜 격식 있게 할까요?"

과제 글이면 학교의 생성형 AI 사용 규정을 확인하도록 한 번 안내한다.

### 8. 인용 관리

사용자가 지정한 양식을 따른다. 지정이 없으면 1단계에서 묻는다.

APA 7판 (본문 괄호형)
```
본문: 대학생의 생성형 AI 사용이 늘고 있다(홍길동, 2025).
참고문헌: 홍길동. (2025). 논문 제목. 학술지명, 권(호), 쪽–쪽. https://doi.org/...
```

KCI 계열 국내 학술지형 (각주형)
```
본문: 대학생의 생성형 AI 사용이 늘고 있다.¹
각주: ¹ 홍길동, 「논문 제목」, 『학술지명』 권(호), 2025, 쪽.
```

간략형 (블로그·칼럼)
```
본문: 한국교육개발원 2025년 보고서에 따르면 ...
글 끝: 참고 자료 — 기관명, 「보고서 제목」, 2025, URL
```

위 예시의 이름·제목은 형식 설명용 자리표시다. 실제 원고에는 3단계에서 확인한 서지 정보만 쓴다.

참고문헌 목록은 작업 내내 따로 유지한다.

```
## 참고문헌
1. [저자]. ([연도]). [제목]. [발행처]. [URL] — 원문 대조: 확인
2. ...
```

### 9. 최종 점검

전체 원고를 받으면 아래 양식으로 검토한다.

```
# 전체 원고 검토

## 총평
- 강점: [2~3개]
- 가장 먼저 고칠 점: [1개]

## 구조와 흐름
- [절 순서, 연결, 분량 배분]

## 내용과 근거
- [주장의 설득력, 근거 충분성, 사례 적절성]

## 인용
- 출처 없는 주장 목록:
  1. [문장] — [위치]
  2. [문장] — [위치]
- 원문 대조 미확인 항목: [목록]
- 인용 양식 불일치: [목록]

## 가독성
- [문장 길이, 문단 길이, 반복 표현]

## 고칠 점 (위치별)
1. 도입: [구체 수정]
2. 본문: [구체 수정]
3. 결론: [구체 수정]
4. 제목: [필요하면 대안 2~3개]

## 제출 전 체크리스트
- [ ] 모든 수치·인용에 출처가 있다
- [ ] 출처 URL을 직접 열어 원문과 대조했다
- [ ] 인용 양식이 하나로 통일되어 있다
- [ ] 절과 절 사이 연결이 자연스럽다
- [ ] 결론이 본문 내용과 맞는다
- [ ] 맞춤법·띄어쓰기를 확인했다
- [ ] 과제 분량과 형식 조건을 지켰다
```

## 예시

### 예시 1: 대학 리포트 전체 흐름

사용자: "교양 수업 리포트로 대학생의 생성형 AI 사용 실태를 쓰려고 해. 같이 써 줘."

진행:

1. 독자·분량·인용 양식을 묻는다 (교수가 APA 지정)
2. 범위 확인 검색으로 쟁점(사용 목적, 학습 효과, 학업 윤리)과 핵심 출처 3개를 정리한다
3. 쟁점을 반영한 개요를 만들고 조사 필요 항목 4개를 표시한다
4. 2절 항목을 조사하고 원문 대조 상태를 표시한다. 확인되지 않은 수치 1개는 빼 둔다
5. 사용자가 도입부를 쓰면 대안 3개를 낸다
6. 사용자가 절을 쓸 때마다 피드백한다
7. 전체 원고를 점검하고 출처 없는 주장 2개를 목록으로 돌려준다

결과: 사용자가 직접 쓴 문장으로 구성되고, 모든 수치가 원문 대조를 거친 리포트.

### 예시 2: 도입부 개선

사용자 원래 도입부:
> "요즘 AI가 많이 쓰인다. 이 글에서는 대학생의 AI 사용에 대해 알아보겠다."

분석: 일반론으로 시작하고, 글을 읽어야 하는 이유가 없다. "알아보겠다"는 범위를 알려 주지 않는다.

대안:

대안 1 (단언형)
> "대학생에게 생성형 AI는 이미 검색창 다음으로 여는 도구가 되었다. 문제는 사용 여부가 아니라 사용 방식이다."
작동 이유: 쟁점을 '사용 여부'에서 '사용 방식'으로 옮겨 글의 범위를 한 번에 보여 준다.

대안 2 (경험·장면형)
> "[본인 경험을 넣는 자리 — 예: 과제 마감 전날 AI를 처음 열어 본 장면]"
작동 이유: 독자가 장면을 떠올리며 들어온다. 사용자의 실제 경험이 있을 때만 쓴다.

대안 3 (데이터형)
> "[3단계에서 원문 대조를 마친 조사 수치]에 따르면 ..."
작동 이유: 첫 문장에서 근거를 제시해 학술적 신뢰를 만든다. 확인된 수치가 없으면 이 대안은 쓰지 않는다.

### 예시 3: 절별 피드백

사용자: "2절 '학습 효과' 다 썼어. 봐 줘."

```
# 피드백: 2절 학습 효과

## 잘된 점
- 긍정 효과와 부정 효과를 나눠 정리했다
- 문단마다 첫 문장에 주장을 두었다

## 고칠 점

### 근거
- "AI를 쓰면 성적이 오른다"는 문장에 출처가 없다 → 3단계 조사 필요 목록에 추가하거나 문장을 "성적 변화에 대한 연구 결과는 엇갈린다"처럼 근거 범위 안으로 좁힌다

### 흐름
- 부정 효과 문단이 긍정 효과보다 먼저 나온 뒤 다시 긍정으로 돌아간다 → 긍정, 부정, 조건 순으로 재배열하면 3절 '사용 방식' 논의로 이어진다

## 문장 단위 수정

원문:
> "AI는 학생들에게 도움이 되기도 하고 안 되기도 한다."

수정안:
> "AI는 개념 설명을 받을 때는 학습을 돕지만, 답을 그대로 옮길 때는 이해를 건너뛰게 만든다."

이유: '도움이 된다/안 된다'를 어떤 사용 방식에서 갈리는지로 구체화했다.

## 생각해 볼 질문
- 3절에서 제안할 '사용 방식'의 기준을 2절 결론에 미리 깔아 둘 것인가?
```

## 글 유형별 흐름

| 유형 | 순서 |
|---|---|
| 대학 리포트 | 조건 확인(인용 양식 포함) → 범위 확인 검색 → 개요 → 조사·원문 대조 → 절별 작성·피드백 → 최종 점검 |
| 에세이·칼럼 | 관점 정하기 → 짧은 개요 → 도입부 → 본문 한 번에 작성 → 흐름 점검 |
| 블로그·뉴스레터 | 도입부 아이디어 → 짧은 개요 → 한 번에 초안 → 링크·명확성 점검 |
| 설명 글·튜토리얼 | 단계 개요 → 예시 작성 → 설명 추가 → 따라 해 보기 점검 → 자주 막히는 지점 추가 |

## 작업 요령

1. 절 하나씩 피드백을 받는다
2. 조사 결과는 research.md 같은 별도 파일이나 메모에 모은다
3. 초안 버전을 나눠 저장한다 (draft-v1, draft-v2)
4. 소리 내어 읽어 걸리는 문장을 찾는다
5. 마감 시간을 정해 단계별로 끊는다

## 권장 파일 구성

```
리포트폴더/
├── outline.md      개요
├── research.md     조사 결과와 원문 대조 상태
├── draft-v1.md     1차 초안
├── draft-v2.md     수정 초안
├── final.md        제출본
└── sources/        참고 자료 원문
```

## 지켜야 할 원칙

조사:
- 인용 전 출처를 확인한다
- 가능한 최신 자료를 쓴다
- 서로 다른 관점을 함께 다룬다
- 원 출처(1차 자료)를 링크한다

피드백 요청 (사용자에게 안내):
- 원하는 것을 구체적으로 묻는다: "너무 어렵게 쓰였나?"
- 걱정되는 지점을 말한다: "이 절이 늘어지는 것 같다"
- 대안을 요청한다: "이걸 다르게 설명하면?"

문체:
- 본인이 쓴 글 샘플을 공유한다
- 원하는 어조를 알려 준다
- 맞는 제안과 맞지 않는 제안을 표시한다
