# write-lab-report

대화창에 붙여 넣은 실습 메모를 최대 A4 2쪽의 실습 보고서 초안으로 정리한다. 분량 하한은 두지 않는다.
초안은 대화창 텍스트로 보여 주고, 사용자가 승인한 뒤에만 .docx 파일을 만든다.

## 절대 규칙

- 메모에 없는 실습 결과·수치·관찰 내용을 지어내지 않는다.
- 근거는 두 가지뿐이다. ① 사용자가 붙여 넣은 메모 ② 이 대화에서 사용자가 답한 내용.
- 근거가 없는 칸은 문장을 만들어 채우지 않고 "확인 필요"로 표시한다.
- 메모 내용이 애매하면 해석해서 쓰지 않고 "확인 필요"로 표시한 뒤 무엇이 애매한지 한 줄로 적는다.

## 문체 규칙

- 합니다체로 쓴다. 축약형을 쓰지 않는다("됐습니다" → "되었습니다").
- 한 문장은 60자 이내로 쓴다. 넘으면 두 문장으로 나눈다.
- 과장 표현을 쓰지 않는다. 예: 매우, 완벽한, 획기적인, 놀라운, 엄청난.
- "~것 같습니다"를 쓰지 않는다. 확인한 사실은 단정하고, 확인하지 못한 것은 "확인 필요"로 표시한다.

## 진행 순서

각 단계 결과를 보여 주고 확인을 받은 뒤 다음 단계로 넘어간다.

### 1단계. 메모 확인

1. 메모를 읽고 문장마다 목적·방법·결과·느낀 점 중 어디에 해당하는지 나눈다.
2. 어디에도 넣기 어려운 내용은 "분류 보류"로 따로 모은다.
3. 머리 정보 5개를 메모에서 찾는다: 과목명, 주차, 실습 날짜, 이름, 학번.
4. 메모에 없는 머리 정보는 한 번에 묻는다. 예시:

```
보고서 머리에 들어갈 정보가 메모에 없습니다. 아래 항목을 알려 주십시오.
과목명:
주차:
실습 날짜:
이름:
학번:
```

5. 사용자가 답하지 않은 머리 정보는 "확인 필요"로 둔다.
6. 분류 결과를 표로 보여 준다.

| 항목 | 메모에서 찾은 내용 | 상태 |
|---|---|---|
| 목적 | ... | 있음 / 없음 |
| 방법 | ... | 있음 / 없음 |
| 결과 | ... | 있음 / 없음 |
| 느낀 점 | ... | 있음 / 없음 |
| 분류 보류 | ... | - |

7. 사실 보강 질문을 한 번에 묻는다. 메모에 이미 있는 항목은 묻지 않는다.
   - 실습 환경은 무엇이었습니까? (프로그램, 장비)
   - 사용한 파일·재료의 이름과 내용은 무엇입니까?
   - 처음 쓴 코드·명령과 고친 코드·명령은 무엇입니까?
   - 오류가 났다면 오류 메시지는 무엇이었습니까?
   - 결과를 어떤 방법으로 확인했고, 무엇이 나왔습니까?
8. "모름"이라고 답할 수 있다고 알린다.

### 2단계. 느낀 점 끌어내기

메모에 느낀 점이 있으면 이 단계를 건너뛴다.
없으면 아래 질문 중 메모 내용에 맞는 2~3개를 골라 한 번에 묻는다.

- 실습에서 가장 오래 막힌 지점은 어디였습니까?
- 예상과 다르게 나온 결과가 있었습니까?
- 다음 실습에서 바꿔 볼 방법은 무엇입니까?
- 이번 실습으로 새로 알게 된 점은 무엇입니까?

사용자의 답만으로 느낀 점을 쓴다. 답이 없으면 "확인 필요"로 둔다.

### 3단계. 초안 작성

아래 구조로 쓴다.

```
실습 보고서

과목명: / 주차: / 실습 날짜: / 이름: / 학번:

1. 실습 목적
2. 실습 방법
3. 실습 결과
4. 느낀 점
```

- 실습 목적: 2~4문장. 이번 실습에서 확인하려던 것을 쓴다. 실습 주제를 그대로 되풀이하는 문장은 쓰지 않는다.
- 실습 방법: 한 일과 사용한 코드·명령을 번호 리스트로 쓴다. 실습 환경과 사용 파일은 번호 리스트 앞에 불릿으로 둔다.
- 실습 결과: "단계 | 결과" 표로 쓴다. 오류가 난 시행도 한 행으로 넣는다. 메모와 답변에 있는 값만 넣고, 방법에 쓴 코드를 다시 적지 않는다.
- 느낀 점: 3~5문장. 1단계 메모와 2단계 답변만 근거로 쓴다.
- 전체 분량은 최대 A4 2쪽이다. 메모에 없는 내용이나 반복으로 분량을 늘리지 않는다.

### 4단계. 빈 항목 표시

- 필수 항목(목적·방법·결과·느낀 점)에 근거가 없으면 "확인 필요"를 붙인다.
- 선택 항목(실습 환경, 사용 파일 등)에 답이 없으면 그 줄을 지운다.
- 남은 "확인 필요"가 있을 때만 초안 맨 아래에 "확인 필요 목록"을 둔다. 항목마다 무엇을 채워야 하는지 한 줄로 적는다.

### 5단계. 점검

초안을 아래 5개 기준으로 점검한다.

| 번호 | 점검 기준 | 어긋났을 때 처리 |
|---|---|---|
| ① | 메모·답변에 없는 결과가 들어갔는가 | 해당 문장을 지우고 "확인 필요"로 바꾼다. 새 문장을 쓰지 않는다 |
| ② | 빈 항목에 "확인 필요"가 붙었는가 | 빠진 곳에 "확인 필요"를 붙인다 |
| ③ | 합니다체인가 | 합니다체로 고친다 |
| ④ | 한 문장이 60자 이내인가 | 두 문장으로 나눈다 |
| ⑤ | 과장 표현·"~것 같습니다"가 없는가 | 단정문으로 고치거나 "확인 필요"로 바꾼다 |

- 어긋난 문장은 자동으로 고친다.
- 고친 뒤 다시 점검한다. 최대 2회 반복한다.
- 2회 뒤에도 남은 문제는 위치·기준 번호·이유를 보고한다.
- 초안 아래에 수정 내역표를 붙인다.

| 위치 | 기준 | 고치기 전 | 고친 후 |
|---|---|---|---|
| 3. 실습 결과 2번째 문장 | ① | ... | 확인 필요 |

### 6단계. 승인 후 .docx 생성

1. 점검을 마친 초안을 보여 주고 승인을 받는다.
2. 사용자가 고칠 곳을 말하면 반영한 뒤 5단계 점검을 다시 한다.
3. 승인받으면 docx 스킬을 불러 .docx 파일을 만든다.
4. 파일명: YYMMDD_과목명_N주차_실습보고서.docx (머리 정보가 "확인 필요"면 해당 자리에 "미정"을 쓴다).
5. 파일에는 수정 내역표를 넣지 않는다. "확인 필요" 표시는 그대로 남긴다. 코드·명령은 고정폭 글꼴로 써서 본문과 구분한다.
6. 파일 링크와 한 줄 요약으로 끝낸다.

## 하지 않는 것

- 승인 전에 .docx 파일을 만들지 않는다.
- 메모에 없는 이론 설명·참고문헌을 덧붙이지 않는다.
- 교수님 평가를 의식한 꾸밈 문장을 넣지 않는다.
