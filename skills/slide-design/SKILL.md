# slide-design

원문(칼럼·보고서·회의 메모·활동 기록)을 발표 슬라이드로 바꾼다. 일은 두 단계로 나눈다.

- 1단계 기획: 클로드가 장별 기획표를 쓰고 사용자가 확인한다.
- 2단계 조판: 승인된 기획표를 scripts/build_slides.py 가 정해진 디자인으로 조판한다.

디자인은 스크립트와 references/theme.md 가 정한다. 기획표 문구가 바뀌어도 색·글꼴·배치는 같게 나온다.

## 절차

1. 원문을 읽고 내용 덩어리로 나눈다.
2. 표지와 마무리를 포함해 5~8장으로 장 수를 정한다.
3. 덩어리마다 장 유형 6종(표지·요점·표·흐름·비교·마무리) 중 1개를 고른다. 선택 기준은 references/plan-table.md 를 따른다.
4. 장마다 제목 · 핵심 문장 · 본문 항목 3~4개 · 근거를 쓴다.
5. 기획표는 6열(장 · 장 유형 · 제목 · 핵심 문장 · 본문 항목 · 근거)로 쓰되, 대화창에는 "장 · 제목 · 핵심 문장" 3열 표만 보여 주고 멈춘다. 근거가 "없음"인 장은 핵심 문장 끝에 (근거 없음)을 붙인다. 사용자가 6열 전체를 요청하면 6열로 보여 준다. 파일은 만들지 않는다. 기획표 끝에 "고칠 곳을 말하거나, 승인하면 조판한다" 한 줄을 붙인다.
6. 사용자가 고칠 곳을 말하면 기획표를 고쳐 전체를 다시 보여 주고 멈춘다.
7. "승인" 또는 "조판해 줘"를 받으면 기획표를 JSON 파일로 옮기고 스크립트를 실행한다.
   ```
   python3 scripts/build_slides.py plan.json out.pptx
   ```
   JSON 형식은 references/plan-table.md 의 "JSON 형식"을 따른다. 스크립트 경로는 이 스킬 폴더 기준이다. python-pptx 가 없으면 스크립트가 설치를 시도한다.
8. 출력 끝의 넘침 점검 결과를 1줄로 보고하고 pptx 파일을 제공한다.
   - 예: "넘침 경고 0건." 또는 "넘침 경고 2건 — 03장 제목, 05장 비교 2행. 줄일 문구를 고르면 다시 조판한다."
   - 경고가 있어도 파일은 제공한다. 문구를 줄이는 결정은 사용자가 한다.

## 수정 요청 처리

- 문구·장 순서·장 유형을 바꾸는 요청은 기획표를 고친 뒤 같은 스크립트로 다시 조판한다.
- 색·글꼴을 바꾸는 요청은 references/theme.md 의 "설정값" 표만 고치고 다시 조판한다. 스크립트는 고치지 않는다.
- 다시 조판할 때도 장 유형 6종과 정해진 배치를 그대로 쓴다.

## 금지

- 원문에 없는 숫자·사실을 넣지 않는다. 원문에 근거가 없는 항목은 근거 칸에 "없음"이라 쓰고 사용자에게 확인을 받는다.
- 승인 전에 조판하지 않는다. 승인 전에는 pptx·JSON 파일을 만들지 않는다.
- 장 유형 6종 외 레이아웃을 쓰지 않는다. python-pptx 로 직접 도형을 그리거나 다른 조판 방법으로 바꾸지 않는다.
- 브랜드 이름·강사 이름을 슬라이드에 넣지 않는다. 왼쪽 위 제목 줄과 하단 문구는 사용자가 정한 문구만 쓴다.
- 기획표 단계에서 디자인(색·글꼴·위치)을 논의하지 않는다. 기획표는 내용만 다룬다.
