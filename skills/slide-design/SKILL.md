# slide-design

원문(칼럼·보고서·회의 메모·활동 기록)을 발표 슬라이드로 바꾼다. 일은 4단계로 나누고, 단계마다 결과를 보여 준 뒤 멈춘다.

| 단계 | 보여 주는 것 | 다음 단계 신호 |
|---|---|---|
| 1. 결론 · 흐름 | 가정, 원문 문단 번호와 분류, 한 문장 결론, 발표 흐름 5칸 | "다음" |
| 2. 장 구성 | 4열 요약표(장 · 제목 · 핵심 문장 · 시간), 장 유형 순서, 점검 결과 | "다음" · "상세 보여 줘" |
| 3. 장별 상세 | 장마다 블록(유형 · 제목 · 핵심 문장 · 본문 항목 · 근거 · 시간 · 노트), 점검 결과 | "승인" · "조판해 줘" |
| 4. 조판 | pptx 파일, 넘침 점검 1줄 | — |

디자인은 scripts/build_slides.py 와 references/theme.md 가 정한다.

## 진행 표시줄

응답 첫 줄에 현재 위치를 둔다. 끝난 단계 ✓, 현재 단계 ●, 남은 단계 ○.

```
진행: 1 결론·흐름 ✓ → 2 장 구성 ● → 3 장별 상세 ○ → 4 조판 ○
```

응답 끝에는 다음 단계 신호를 1줄로 적는다. 화면 예시는 references/stage-screens.md 를 따른다.

## 절차

1. 결론 · 흐름
   - 원문 다음으로 발표 시간을 묻는다. 빠진 항목은 planning.md 1절 기준으로 가정해 적는다.
   - 원문 문단에 번호를 붙이고 사실·주장·예시·확인 필요로 나눈다(planning.md 2절).
   - 한 문장 결론과 발표 흐름 5칸을 정한다(planning.md 3절). 보여 주고 멈춘다.
2. 장 구성
   - 발표 시간에 맞춰 5~8장과 장별 시간을 정한다(planning.md 4절).
   - 장마다 장 유형 15종 중 1개를 고르고(references/types.md) 제목·핵심 문장을 쓴다.
   - 4열 요약표, 장 유형 순서, 점검 결과(planning.md 7절 단계 2)를 보여 주고 멈춘다.
3. 장별 상세
   - 장마다 본문 항목 3~4개 · 근거(문단 번호) · 노트를 채운다(planning.md 5~6절).
   - 근거가 "없음"인 장은 핵심 문장 끝에 (근거 없음)을 붙인다.
   - 장별 블록과 점검 결과(planning.md 7절 단계 3)를 보여 주고 멈춘다. 파일은 만들지 않는다.
4. 조판
   - "승인" 또는 "조판해 줘"를 받으면 기획을 JSON 파일로 옮기고(노트 포함) 스크립트를 실행한다.
     ```
     python3 scripts/build_slides.py plan.json out.pptx
     ```
     JSON 형식은 plan-table.md 4절과 types.md 3절을 따른다. 경로는 스킬 폴더 기준이다. python-pptx 가 없으면 스크립트가 설치를 시도한다.
   - 넘침 점검 결과를 1줄로 보고하고 pptx 파일을 제공한다. 예: "넘침 경고 0건." 또는 "넘침 경고 2건 — 03장 제목, 05장 비교 2행. 줄일 문구를 고르면 다시 조판한다."
   - 경고가 있어도 파일을 제공하고, 줄일 문구는 사용자가 정한다.

## 단계 운영 규칙

- 한 응답에 한 단계만 보여 준다. 사용자가 "한 번에 보여 줘"를 요청하면 1~3단계를 이어서 보여 주고 3단계 끝에서 멈춘다.
- 1·2단계에서 바로 "승인"을 받아도 3단계를 한 번 보여 준 뒤 조판한다. 조판 전에 장별 내용을 반드시 한 번 확인받는다.
- "기획만"을 요청하면 3단계에서 끝낸다.
- 확인된 내용은 다시 묻지 않는다.

## 수정 요청 처리

- 현재 단계에서 고친 결과를 다시 보여 주고 멈춘다. 변경 내용을 표 위에 1~3줄로 적는다.
- 앞 단계(결론·흐름, 장 구성)가 바뀌면 그 뒤 단계의 내용도 함께 고친다. 진행 표시줄은 바뀐 단계로 되돌린다.
- 3단계에서 바뀐 장은 장 번호 옆에 "수정"으로 표시한다.
- 조판 뒤 문구·장 순서·장 유형 수정은 기획을 고친 뒤 같은 스크립트로 다시 조판한다.
- 색·글꼴 수정은 references/theme.md 의 "설정값" 표만 고치고 다시 조판한다. 스크립트는 고치지 않는다.

## 금지

- 원문에 없는 숫자·사실·사례를 넣지 않는다. 근거가 없으면 근거 칸에 "없음"이라 쓰고 확인받는다.
- 4단계 전에는 pptx·JSON 파일을 만들지 않는다.
- 장 유형 15종 외 레이아웃을 쓰지 않는다. python-pptx 로 직접 도형을 그리거나 다른 조판 방법으로 바꾸지 않는다.
- 브랜드 이름·강사 이름을 슬라이드에 넣지 않는다. 왼쪽 위 제목 줄과 하단 문구는 사용자가 정한 문구만 쓴다.
- 1~3단계에서 디자인(색·글꼴·위치)을 논의하지 않는다. 기획은 내용만 다룬다.
