# 기획표 규칙

## 1. 기획표 8열

| 열 | 내용 | 규칙 |
|---|---|---|
| 장 | 번호 | 5~8장 |
| 장 유형 | 15종 중 1개 (types.md) | 1장은 표지, 마지막 장은 마무리 또는 질문 |
| 제목 | 장 제목 | 20자 이내, 명사형 |
| 핵심 문장 | 이 장에서 남길 한 줄 | 40자 이내 |
| 본문 항목 | 화면에 들어갈 내용 | 3~4개, 개조식 |
| 근거 | 원문 위치 | 문단 번호로 쓴다. 원문에 없으면 "없음" |
| 시간 | 이 장의 발표 시간 | 합이 발표 시간과 같다 (planning.md 4절) |
| 노트 | 발표자 노트 | 1~2문장, 화면 문구 반복 금지 |

## 2. 장 유형 선택 기준

15종 목록 · 고르는 기준 · 원문 조건은 types.md 1~2절을 따른다. 판단이 갈릴 때 아래를 먼저 본다.

- 숫자가 3개 이상 나란히 있으면 요점보다 표를 고른다. 숫자 크기 차이가 메시지면 막대를 고른다.
- 날짜가 붙은 순서는 타임라인, 날짜 없는 순서는 흐름 또는 세로 단계, 순서 없는 할 일 목록은 마무리 항목으로 둔다.
- 비교할 두 시점(9월·10월, 계획·실제)이 원문에 모두 있을 때만 비교를 쓴다.

## 3. 글자 수 기준 (넘침 점검 상한의 근거)

| 자리 | 기준 |
|---|---|
| 표지 제목 | 2줄, 줄당 10자 안팎. 줄바꿈 위치는 "\n"으로 지정 |
| 본문 장 제목 | 20자 이내 (상한 24자) |
| 핵심 문장 | 40자 이내 |
| 요점 키 · 값 | 키 6자 이내, 값 2줄 이내 |
| 비교 칸 | 칸당 2줄 이내 |
| 흐름 단계명 · 설명 | 5칸일 때 단계명 8자, 설명 줄당 8자 안팎 |
| 마무리 항목 | 줄당 40자 이내 |

## 4. JSON 형식

승인 뒤 기획표를 아래 형식으로 옮긴다. 근거·시간 열은 JSON에 넣지 않는다. 노트는 장마다 "notes"로 넣는다.

```json
{
  "meta": {"title_line": "본문 장 왼쪽 위 제목 줄", "footer": "왼쪽 아래 하단 문구"},
  "slides": [
    {"type": "표지", "kicker": "제목 위 작은 줄", "title": "첫 줄\n둘째 줄",
     "message": "기간 · 작성자", "items": [["작은 줄", "큰 줄"], ["작은 줄", "큰 줄"]]},
    {"type": "요점", "title": "제목", "message": "핵심 문장",
     "items": [["키", "값"], ["키", "값"], ["키", "값"]]},
    {"type": "표", "title": "제목", "message": "핵심 문장",
     "headers": ["열1", "열2", "열3"], "rows": [["칸", "칸", "칸"]], "highlight_row": 2},
    {"type": "흐름", "title": "제목", "message": "핵심 문장",
     "steps": [{"name": "단계명", "desc": ["설명 1", "설명 2"]}]},
    {"type": "비교", "title": "제목", "message": "핵심 문장", "left": "전", "right": "후",
     "emphasis": "right", "pairs": [["항목", "왼쪽", "오른쪽"]]},
    {"type": "마무리", "title": "제목", "message": "핵심 문장", "items": ["할 일 1", "할 일 2"], "notes": "발표자 노트"}
  ]
}
```

- `type`은 15종(types.md) 중 하나만 쓴다. 다른 값이면 스크립트가 멈춘다. 신규 9종 JSON은 types.md 3절에 있다.
- 비교 `emphasis`는 강조할 쪽(right · left · none)이다. 없으면 right.
- 요점 `items`는 `["키", "값"]` 또는 `"키: 값"` 문자열로 쓴다.
- 표 `highlight_row`는 강조할 행 번호(1부터)다. 없으면 뺀다.
- 비교 `pairs`에서 항목 칸이 필요 없으면 `["왼쪽", "오른쪽"]` 두 칸으로 쓴다.
- 흐름 `steps`는 `["단계명", "설명"]`로도 쓸 수 있다.
- `notes`는 모든 장 유형에 쓸 수 있다. 없으면 뺀다.
- meta 의 두 값은 사용자가 정한다. 정하지 않았으면 원문 제목을 title_line 에, 작성자 · 기간을 footer 에 쓴다.

## 5. 예시 (원문: 동네 독서 모임 10월 활동 보고)

시간·노트 열은 생략했다. 대화창 기획 화면은 planning.md 8절 예시를 따른다.

| 장 | 장 유형 | 제목 | 핵심 문장 | 본문 항목 | 근거 |
|---|---|---|---|---|---|
| 1 | 표지 | 책방골목 독서 모임 10월 활동 보고 | 기간 10/1~10/31 · 작성 운영진 3명 | 모임 4회 진행 / 평균 참석 11명 | 제목 · 기간 줄 |
| 2 | 요점 | 10월 활동 요약 | 4회 모두 진행했고 읽은 책 2권을 마쳤다 | 모임 4회 / 읽은 책 2권 / 토론 메모 4건 공유 | 1~2번째 줄 |
| 3 | 비교 | 9월과 10월 참석 | 평균 참석이 8명에서 11명으로 늘었다 | 9월 평균 8명 / 10월 평균 11명 | 1번째 줄 |
| 4 | 표 | 회비 현황 | 간식비 54,000원을 쓰고 186,000원이 남았다 | 간식비 지출 54,000원 / 회비 잔액 186,000원 | 3번째 줄 |
| 5 | 흐름 | 11월 준비 순서 | 장소를 먼저 정해야 안내문과 투표를 보낸다 | 장소 결정 / 장소 예약 / 신규 회원 안내문 / 연말 모임 투표 | 4~5번째 줄 (순서는 없음 — 확인 필요) |
| 6 | 마무리 | 11월 결정과 할 일 | 모임 장소를 구립도서관 세미나실로 옮길지 정한다 | 장소 예약 / 신규 회원 안내문 / 연말 모임 날짜 투표 | 4~5번째 줄 |

고칠 곳을 말하거나, 승인하면 조판한다.
